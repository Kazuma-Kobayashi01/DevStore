# 需求与决策记录

## 用户目标

开发一个 Swift 原生 macOS 开发环境管理器：CLI + MCP Server 给 Agent 调用，SwiftUI GUI 给用户管理。SDK/runtime 可放在外置 SSD 的 APFS 磁盘映像中，使用时挂载，停用时卸载；能够转移、更新、备份、恢复与回滚。

初始评估范围是 Go、Rust、.NET/C#、Flutter、Android。用户明确要求先只读扫描，评估安装位置、版本、架构、占用、依赖、权限、链接、缓存和用户数据；未经确认不移动、删除、修改原环境或执行迁移。随后要求暂不编写管理器代码，先完成评估和实验。

## 决策演变

1. 初始讨论 SDK 和缓存拆分；一度设计固定 SDK 只读、缓存可写的双镜像模型。
2. 加入压缩能力，区分可写 sparse bundle 的空闲回收与停用压缩归档。
3. 用户取消只读要求，以最大程度独立化为优先；SDK、工具管理器、混合状态目录允许写入，Flutter 重新纳入后续适配。
4. 用户决定先测试笔记本上的 Miniconda，改为一个卷；若通过，其他环境也默认一卷。
5. Miniconda 本机固定路径单卷实验通过，形成当前 v3：**每个环境一个可写 APFS 卷，缓存作为卷内数据分类管理**。
6. 用户要求将全部材料整理至 `Documents/Code/DevStore`，创建 docs，准备移交 Claude。当前交接不包含 Swift 应用实现，也不代表授权批量迁移其他环境。
7. 移交 Claude 后形成 [v3 数据模型](design/v3数据模型.md)，用户逐条决定：主机登记用 JSON/JSON Lines；常驻授权仅限 mount 级、按环境、默认关；活动映像默认不加密，导出归档时可选加密；同一环境映像可分属多个存储库但只有一个 active；**同 kind 初版即支持多槽**；compact 先实验再定。
8. 用户授权执行 compact 与多槽实验（A10 中断测试未含）：compact 开放为 mutate 操作、必须临时副本流程；多槽在本机通过。发现现有 Miniconda 映像中有原安装路径的二进制残留，作为已知警告。

## 当前约定

- 固定挂载：`~/.local/dev/<kind>/<slot>`，是真实挂载点；默认槽位 `current`，同 kind 可多槽同时挂载，槽位创建后固定。
- 活动格式：可写 APFS sparse bundle；不强制 SDK 只读、不强制另建缓存卷。
- SDK、原生工具状态、用户工具、必要附属运行时和缓存尽量同卷；优先保持官方结构。
- 压缩：停用后 LZFSE 归档，按需支持 LZMA；恢复成新的可写卷后使用。compact 是另一项能力，当前尚未实验验收。
- 更新前检查点，失败后恢复；转移只复制正常卸载的映像，保持固定使用路径并验证。
- .NET 可从官方二进制包建立新实例，不必搬动当前 root 所有的安装。
- 原项目源码、宿主系统能力、Xcode、系统身份与秘密按具体需要登记，不假定自动随 SDK 独立化。
- 每个适配器分别证明其可用性；Miniconda 的成功不等于其他语言、外置盘或跨 Mac 已通过。

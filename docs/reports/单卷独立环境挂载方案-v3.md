# 单卷独立环境挂载方案 v3

日期：2026-10-29。默认替代 v1/v2 的双卷设计。依据：[Miniconda 单卷实验](Miniconda单卷实验结果-20261029.md)在本机完成首次运行、重挂、压缩恢复三轮验证；其他语言尚未因此自动获得兼容性保证。

## 默认模型

**每个受管理环境一个可写 APFS 卷。** SDK/runtime、工具管理器、用户工具、持久状态、必要附属依赖与缓存共同保存；不再要求另建缓存卷。工具原生的混合目录优先保持完整，减少路径拼接、跨卷链接和备份一致性问题。

缓存是数据分类，不再是卷分类。清理操作只能针对适配器明确认定可重建的数据，不能清空整个混合目录或整个卷。项目源码默认仍在用户项目目录；确需随环境搬运的工作区另行选入并标记为必须备份的数据。登录/签名秘密不自动导入，私密环境和归档的加密策略需明确选择。

## 位置与身份

| 对象 | 位置及规则 |
|---|---|
| 运行卷 | `~/.local/dev/<kind>/<slot>`，实际可写挂载点；默认槽位 `current`（2026-10-29 改为支持多槽，见[数据模型](../design/v3数据模型.md)） |
| 活动映像 | `<存储库>/environments/<kind>/<environment-id>/environment.sparsebundle`；可在内置盘或外置 SSD |
| 卷内 SDK | 保留发行物的完整结构，实际子目录由适配器声明；Miniconda 实验使用 `current/miniconda3` |
| 卷内状态和缓存 | 原生目录或 `state`、`cache`、`tools`、`deps`；不强制搬开工具自己的内部缓存 |
| 检查点与归档 | `<存储库>/checkpoints/<environment-id>/<checkpoint-id>.dmg`，停用时生成，恢复为新可写映像 |
| 主机登记 | 本机定位与事务日志；环境内保留足够清单供导入重建，不能让主机登记成为不可恢复的唯一配置 |

存储库路径与运行路径分离。同一 kind 可有多个环境各占一个槽位同时挂载（原"每类同时一个活动实例"已由用户改为初版支持多槽）；同一逻辑实例不得在多台主机同时读写。卷 UUID、当前设备、映像路径和登记身份共同核对；复制映像可能保留 UUID，不能只凭 UUID 判定。

活动卷可变，版本和组件应在变更后重新发现；不可变检查点有自己的内容清单及摘要。容量可分别统计 SDK、状态、依赖和缓存，但它们都属于一个卷。

## 各工具的原则

- Miniconda：base、envs、pkgs、独立配置、用户状态和 pip 缓存同卷；前缀修复后保持固定挂载路径，不只复制目录就宣称可搬运。
- Go：完整 SDK、GOPATH/用户工具和构建/模块缓存同卷；明确选择本卷工具链，记录任何新增工具链。
- .NET：独立官方二进制包、CLI 状态、用户工具、NuGet 包及选中 runtime/workload 同卷；保留原 root 安装，不改系统登记；Apple workloads 等宿主依赖单列。
- Rust：完整 RUSTUP_HOME、CARGO_HOME、代理、用户工具与缓存同卷；不为拆缓存破坏原生锁和安装状态。
- Flutter：完整工作树、内置 Dart、bin/cache、Pub/工具状态同卷；允许原生写入；必要的独立 JDK 等可一并放入 deps。
- Android：SDK/NDK、兼容 JDK、Gradle User Home、Android 用户状态及选定 AVD 同卷；许可证、路径引用、模拟器与宿主能力单独验收。
- 其他语言按同一标准适配；系统解释器、绝对路径、动态库或外部项目引用不能仅靠可写卷消除。

配置只注入受管理子进程，默认不改全局 shell、系统链接、原包管理器或 IDE。适配器应声明所有可定位路径及仍需宿主提供的能力；缺项时报告，不静默借用原安装。需要联网时在具体操作中明确，不把全部环境承诺为离线可用。

## 生命周期与空间管理

创建/导入先建新映像和清单 → 固定路径挂载 → 完整性及运行验证 → 登记为可用。切换前停止任务、正常卸载；卷忙时返回占用，不强制。缺卷时不能写入挂载点底层空目录。

升级或安装组件前建立可恢复检查点。更新写入受管理环境，重新发现版本/组件后验收；失败则将检查点恢复成另一个可写实例，再切换回固定路径。原安装和已验证检查点不自动删除。

- 日常使用：一个 APFS 可写 sparse bundle。
- 空间回收：停用后对临时副本 compact，验证后替换；可能无收益，且不等于压缩已用数据。2026-10-29 实验：卷内删除后卸载不会自动释放，compact 可回收且内容一致（[结果](compact实验结果-20261029.md)）；中断测试未做，须走临时副本流程。
- 压缩归档：卸载后生成 LZFSE 压缩 DMG，按需选择 LZMA；压缩格式只用于存放检查点，不限制日常可写运行。
- 恢复：转成新的可写 sparse bundle，核对内容、模式、链接与代表性运行，再登记。预留原本、归档和恢复卷的空间；不自动删除原本腾空间。
- 转移：只复制已卸载映像，校验后挂回同一固定路径复测；跨用户名、架构和系统版本另验。普通同盘副本不是独立物理备份。

## 统一接口和后续验收

CLI、MCP、GUI 的默认管理单位改为整个环境：检查、预览、挂载、运行、检查点、更新、清理指定缓存、回收空间、归档、恢复、切换和转移。不再将 `sdk/cache/both` 作为默认挂载模式；缓存界面改为卷内分类用量与精确清理范围。

确认绑定环境、映像、路径、操作及影响。全卷删除、原安装迁移、秘密导入、升级及切换均有单独范围；Agent 自报确认不能替代用户授权。普通构建脚本可能访问宿主，不能称为容器隔离。

每个适配器至少验证：禁止读取原安装时的实际运行、关键入口和包来源、管理器写入落点、缓存/状态保留、卸载重挂、检查点恢复，以及原安装不变。通过后再测试外置盘和目标 Mac；测试证据记录已覆盖和未知部分。

当前状态：Miniconda 的本机固定路径单卷与压缩恢复通过；实验卷已卸载，默认 conda 未切换。其他 SDK 沿用一个可写卷的规划，后续逐个复制和验收，未执行批量迁移，也未编写 Swift 管理器应用。

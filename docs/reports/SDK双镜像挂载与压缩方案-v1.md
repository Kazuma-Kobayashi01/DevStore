# SDK 双镜像挂载与压缩方案 v1

> 此稿已由 [可写独立环境挂载与压缩方案 v2](可写独立环境挂载与压缩方案-v2.md) 替代。当前要求已取消 SDK 只读限制，以环境尽可能独立为优先；本文件仅保留设计历史。

日期：2026-10-29。状态：设计稿，未创建映像、下载 SDK、修改现有环境或执行迁移；不包含应用代码。本方案替代上一份评估中“SDK 使用可写 sparse bundle”的设计，原扫描结果仍作参考。

## 1. 共同结构与准入条件

每个受支持的语言环境采用两个独立映像：**固定版本 SDK 的只读映像 + 可重建缓存的可写映像**。本机另外保留用户配置、凭据、证书、工具安装记录和项目；它们是持久状态，不被视为缓存，不需要第三个映像。

“非系统级”指用户可拥有、可独立选择且不需要改写系统路径、系统服务、安装收据或全局包管理器记录的安装。不能因为某个 Homebrew 目录由用户拥有，就直接把它认定为独立 SDK；应复制完整运行所需内容，或使用官方独立二进制包建立新实例，单独验证。

受管理的 SDK 必须满足：

- 保持官方目录结构后，能在自定义位置运行，不必回写 SDK 树；只读挂载下的代表性运行、构建和测试必须通过。
- 所需缓存能定位到独立可写路径；不能把用户配置、密钥、用户安装工具或项目源码当作可丢弃缓存。
- 所有更新、组件安装和自更新都在新的可写准备区完成，冻结后生成新版本映像。运行中的 SDK 永远不原地升级。
- 可以明确固定入口、版本、宿主架构和依赖；不自动改用系统安装或下载另一个工具链来掩盖缺失。
- 对宿主 macOS、Xcode/CLT、JDK、系统库和架构的要求必须登记。这套结构提供可搬运的文件和可控路径，不提供进程隔离。

## 2. 首批支持范围

| 环境 | 严格只读 SDK + 独立缓存 | 设计决定 |
|---|---|---|
| Go | 首批候选，先实验验收 | 完整独立 SDK；`GOCACHE`、`GOMODCACHE` 指向缓存卷。GOPATH 中的用户工具与工作区独立保留；固定 `GOTOOLCHAIN=local`，不在执行阶段自动装工具链 |
| .NET 官方二进制包 | 首批候选，限定基础 SDK/运行时 | 从官方 macOS arm64 `.tar.gz` 包建立用户所有的新实例，并验证官方摘要。完整保存 SDK、自带运行时、packs 等；不改当前 root 所有的安装、收据或链接。`NUGET_PACKAGES` 指向缓存卷，`DOTNET_CLI_HOME` 指向本机持久状态目录 |
| Rust 固定 toolchain | 第二批，适配后验收 | SDK 映像保存实际 toolchain 根目录，直接选择其 `rustc`、`cargo`、`rustdoc`；不把 rustup 自更新和工具链安装放进只读运行流程。Cargo Home 混合缓存、锁、配置、凭据和用户工具，需要专门适配 |
| Android SDK | 第二批，只支持预装组件集合 | 固定平台、Build Tools、NDK 等组合；运行期不执行 sdkmanager 安装、更新或许可证写入。Gradle、Android 用户状态、JDK 和项目 SDK 路径必须另行验证 |
| Flutter | 暂不纳入严格模式 | 本机启动脚本会写 SDK 内的 `bin/cache`、锁、版本标记等，部分流程还会改变其他 SDK 内文件；单独设置 Pub 缓存不够。后续如研究覆盖层或可写工作副本，应明确属于另一种模式 |
| 独立包 Node.js、JDK 等 | 未来候选，不标记为已支持 | 仍须通过同一准入测试；全局包、包管理器状态和构建工具缓存分别处理。尚未据本次扫描确认其独立安装可搬运性 |
| 系统 Python、依赖绝对路径的 venv/框架安装等 | 不在 v1 范围 | 不能假定复制后仍可用；需独立发行物和适配验证，不改变系统自带版本 |

.NET 首轮不承诺 MAUI、额外 workloads、自定义全局工具或任意 SDK 版本自动解析；这些能力需要后续逐项验收。官方支持从二进制归档手动安装，因此可以绕开当前安装器管理关系建立新实例。[Microsoft macOS 安装说明](https://learn.microsoft.com/en-us/dotnet/core/install/macos)。

Rust 的适配底线：不能直接把现有 `~/.cargo` 整体迁入缓存卷。后续为受管理会话建立独立 Cargo Home，统一处理其缓存目录、全局缓存数据库和锁；凭据经本机凭据提供器取得，用户配置经显式导入，用户安装工具落到持久工具目录。初版适配未通过前不启用 Rust 双卷功能，也不把原目录中的部分缓存通过零散链接强行拼接成共享缓存。[Cargo Home](https://doc.rust-lang.org/cargo/guide/cargo-home.html)、[Cargo 配置](https://doc.rust-lang.org/cargo/reference/config.html)。

## 3. 存储库与固定挂载点

物理存储位置与使用路径分离：存储库可以在内置盘或外置 SSD，配置登记其根位置；SDK 使用路径不随外置盘名字变化。不能仅靠 `/Volumes` 下的名称确认磁盘，重连后须核对存储库标识及具体映像身份。

| 内容 | 存储位置示例 | 挂载或使用位置 |
|---|---|---|
| Go 版本映像 | `<存储库>/sdk/go/1.27.3/macos-arm64/sdk.dmg` | `~/.local/dev/go/current`，只读 |
| Go 缓存映像 | `<存储库>/cache/go/default-macos-arm64.sparsebundle` | `~/.local/dev/go/cache`，可写 |
| .NET 版本映像 | `<存储库>/sdk/dotnet/10.0.402/macos-arm64/sdk.dmg` | `~/.local/dev/dotnet/current`，只读 |
| .NET 缓存映像 | `<存储库>/cache/dotnet/default-macos-arm64.sparsebundle` | `~/.local/dev/dotnet/cache`，可写 |
| 登记、配置和事务日志 | 本机 `~/.local/state/dev-environments` | 普通本机目录；不随缓存清理 |
| 项目、密钥与用户工具 | 原项目目录或独立持久目录 | 不纳入两类映像，也不自动更改原位置 |

`current` 和 `cache` 都是真实挂载点，彼此为同级目录；不让 `current` 同时充当符号链接，也不把缓存卷嵌套挂到只读 SDK 里。每个 SDK 在 v1 同时只有一个活动版本；更新或回滚通过卸载旧映像、挂载新映像完成，另一个版本可保留在存储库中。

SDK 映像内根目录直接是该发行物的 SDK 根目录，不增加会破坏工具自身路径识别的包装层。SDK 映像旁保存版本、架构、组件清单、内容清单、摘要和来源信息；导入前校验。

缓存卷内区分“下载依赖”和“构建缓存”。构建缓存按工具链/架构及适配器要求分区；下载依赖只有在工具自身支持并发、校验与锁语义得到验证时才跨版本复用。切换 SDK 不默认清空缓存，也不承诺缓存可跨架构或跨机器直接复用。

## 4. 运行与挂载规则

### 独立挂载，按需组成会话

- 支持只挂 SDK、只挂缓存，或者两者一起挂载。单独挂载不等于自动激活整套环境。
- 版本查询等声明不需要缓存的操作可以仅使用 SDK；构建、恢复依赖等操作通常要求 SDK 和缓存均已就绪。
- 缓存缺失时默认返回明确错误，不自动创建本机备用缓存、不悄悄改用原安装；新建空缓存是单独操作。
- 入口使用挂载后的明确可执行文件。只对启动的子进程设置环境，默认不改 shell 配置、全局 PATH、包管理器链接或 IDE 设置；GUI/IDE 的配置接入是以后单独确认的动作。
- Go 会话映射构建/模块缓存；.NET 会话映射 NuGet 缓存和本机 CLI 状态，并固定相应 `dotnet` 主机、`DOTNET_ROOT` 及架构相关根路径。项目要求其他 SDK、runtime 或组件时报告缺项，不用宿主安装补齐。
- 构建输出默认仍属于项目；只有适配器和用户明确选择时，才放到缓存卷。自定义脚本、插件或构建任务仍可能访问宿主文件，不把这种环境启动方式表述为安全沙盒。

### 挂载事务

预检路径、权限、空闲空间和兼容性 → 获取操作锁 → 挂载所需映像 → 核对映像路径、设备、卷 UUID、读写模式和版本 → 生成会话环境 → 启动任务。

卷 UUID 不是唯一判断依据：复制映像可能保留 UUID，必须结合登记的内容标识、当前设备和映像实际路径。v1 不允许同一逻辑映像的两个副本同时挂载。SDK 再强制只读；缓存允许读写并启用所有权语义，限当前用户使用。

开始会话前检查真实挂载状态；空目录不代表卷已挂载。外置盘缺失或路径变化时保持不可用，不能自动写入挂载点底层目录。SDK、缓存、切换和维护操作有独立状态，组合会话也有整体结果；挂载 SDK 成功而缓存失败时，本次新挂载的 SDK 应正常卸载回退，先前已有的挂载不受影响。

正常停止任务后卸载；卸载整个环境时先释放缓存卷，再释放 SDK 卷。还有任务、文件占用或挂载点工作目录时返回“忙”，不默认强制。仅在已验证卷不再使用时完成操作。缓存可写映像 v1 只由一台主机读写，不在多台机器同时打开，也不放在实时云盘同步流程中使用。

## 5. 压缩与空间管理

“压缩”拆成明确的三项能力，避免把体积减少、空闲回收和虚拟容量混为一谈。

| 功能 | 对象与默认方式 | 使用特性 |
|---|---|---|
| 压缩 SDK 映像 | APFS 内容封装为 **ULFO / LZFSE 只读 DMG** | 默认发布格式；可直接只读挂载使用，无需先解包成完整 SDK 目录；实际体积和耗时需测量 |
| 回收缓存空闲空间 | APFS **UDSB sparse bundle**，卸载后 compact | 保持可写，只尝试回收未使用的带区；不压缩仍在使用的数据，也不改变虚拟容量；可能回收不到空间 |
| 缓存冷归档 | 卸载的缓存副本转为只读压缩 DMG，默认 ULFO，可选 **ULMO / LZMA** | 用于保存、传输和长期停用；恢复构建前必须还原为新的可写 sparse bundle，不能把归档直接当可写缓存 |

SDK 的无压缩对照格式为 UDRO；不提供一个虚构的“APFS 全卷实时压缩”开关。ULFO、ULMO 和 UDSB 属于外层映像格式，内部仍可承载 APFS。压缩率、启动速度和编译速度不预先保证；已有压缩包或高熵文件可能几乎不能再缩小。Apple 将只读压缩映像和可写 sparse bundle 列为不同格式。[Apple 映像格式转换说明](https://support.apple.com/guide/disk-utility/convert-a-disk-image-to-another-format-dskutl1002/mac)。

已从本机 macOS 15.7.9 的 `hdiutil` 帮助和手册确认 ULFO、ULMO、UDRO、UDSB、convert、verify、compact 能力；这仅是功能核验，尚未实际创建、压缩、挂载或测量性能。以本机支持范围为准，不依赖较新系统的 ASIF 格式。手册明确：compact 可能不缩小 sparse bundle；它回收空闲带区，与文件压缩不同。

### 维护事务与保护

压缩、归档、恢复、回收和转移都要求目标映像不在任何本机会话中使用并已正常卸载；v1 不支持在线维护。先检查副本、备份和临时空间，再操作临时目标；不覆盖现有 SDK 映像。缓存回收也默认在临时副本上进行，验证后登记新副本，旧副本在另行确认清理前保留。空间不足则停止，不自动删除旧副本腾空间。

输出映像必须经过结构与内容核对；只读/压缩映像执行适用的映像校验和验证，还需核对 SDK 文件清单、SHA-256、链接、权限和挂载后的代表性测试。可写缓存没有同等的内置镜像校验和，使用卸载状态的文件清单与内容检查；恢复后按适配器验收。验证通过后才更新登记位置；转换失败、断连或取消则保留旧登记和原映像，临时产物标记未完成。

回收不触发缓存删除。清理依赖、按时效删除、清理构建缓存、清除整卷分别是不同动作，需各自列出影响并获得确认。删除缓存后若无网络或原源不可用，不保证离线构建仍能恢复。

界面分别显示：文件逻辑大小、映像已分配空间、虚拟容量、内部可用空间、操作前后映像大小及宿主剩余空间。清理、compact 和压缩的结果单独报告；APFS 克隆共享和快照会影响物理空间回收，不把 `du` 差额直接等同于硬盘释放量。v1 不自动建立内部 APFS 快照，已有快照可能使回收无效，发现后报告，不擅自删除。

缓存可能含私有依赖和源代码，归档与转移不得默认公开；配置和密钥不写入公开清单或普通日志。数据加密是独立选项：实验默认不加密；正式缓存及其归档建议启用加密，SDK 公共发行物默认不加密，私有 SDK 在导入时明确选择。选定加密后转换和恢复不得默默去掉加密，密钥保留本机安全存储，不进入命令行参数或日志。

## 6. 更新、回滚与跨盘转移

更新采用新建版本：在独立可写准备区下载/解包 → 校验发行来源及上游摘要 → 安装选定组件 → 测试 → 正常卸载 → 生成并验证只读压缩映像。SDK 只读运行期不执行包管理器升级、workload 安装、rustup 更新或 sdkmanager 更改；组件变更形成新的内容版本。

.NET 新实例使用用户所有的官方二进制包目录，不复用 `/usr/local/share/dotnet` 的系统登记。SDK 和它需要的 runtime 作为一个明确组件集合打包；缺失的旧 runtime 不因装了新 SDK 就被假定存在。`DOTNET_CLI_HOME` 保存的是可写支持状态，不能全部归类为可删除缓存；NuGet 包使用 `NUGET_PACKAGES` 单独定位。[Microsoft 环境变量说明](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-environment-variables)。

切换或回滚仅在任务停止后进行：记录旧映像身份和环境 → 正常卸载旧 SDK → 挂载并验证新 SDK → 运行探针；失败则卸载新 SDK、挂回旧 SDK并复核。缓存按适配器兼容性选择保留或使用新缓存，不自动改写旧 SDK 或清理用户配置。

跨盘转移只复制已卸载映像：复制到新存储库临时位置 → 校验 → 在同一固定挂载点复测 → 用户确认登记新位置。旧副本和独立备份保留至恢复验证通过，不自动删除。两个副本在同一物理盘不等于独立备份。跨 Mac 使用另外检查最低系统、架构、宿主依赖和可写卷所有权；缓存默认新建或从归档恢复后复验。

## 7. 未来统一接口与模块

共用核心拆成：只读发现、环境适配器、计划生成、映像操作、会话启动、校验与事务日志。CLI、MCP 和 SwiftUI 调用相同服务，避免各自实现挂载规则。

核心数据保持精简：环境规格记录 SDK/版本/架构/宿主依赖、入口、缓存和状态映射、支持的只读操作及验收探针；映像记录角色、格式、路径、来源、内容摘要、卷身份、容量及状态；计划记录选择、影响、临时空间、回滚与确认范围；操作记录阶段、结果及恢复动作。外部清单属于不可信数据，不能定义任意 shell 操作。

| 能力 | CLI 概念命令 | MCP 概念工具 |
|---|---|---|
| 发现、检查、预览 | `scan`、`inspect`、`plan`、`status` | `scan_environments`、`inspect_environment`、`plan_operation`、`get_status` |
| 分别或成组挂载 | `mount --part sdk/cache/both`、`unmount` | `mount_environment`、`unmount_environment` |
| 受管理会话 | `run <environment> -- <sdk-entry> <args>` | `run_environment`，只允许登记的 SDK 入口与授权工作目录 |
| SDK 压缩与验证 | `compress-sdk`、`verify` | `compress_sdk`、`verify_image` |
| 缓存回收与归档 | `compact-cache`、`archive-cache`、`restore-cache` | `compact_cache`、`archive_cache`、`restore_cache` |
| 版本与位置变更 | `switch`、`rollback`、`relocate` | `switch_environment`、`rollback_environment`、`relocate_images` |

这些只是接口设计，不是已经可运行的命令。只读 inspect/plan 返回影响预览；写入或挂载动作要求本机可验证的用户确认，绑定环境、源/目标、映像身份、模式和计划有效期。Agent 不能用自己传入的 `confirmed=true` 代替确认。临时导出/扫描不修改现有环境；不默认开放 SDK 删除、任意 shell、全局 PATH 修改或无界文件访问。运行编译器可能执行项目插件和构建脚本，因此 `run` 的授权不能只按“SDK 入口合法”判断为纯只读。

SwiftUI 中将“压缩 SDK”“回收缓存空间”“归档缓存”显示为三个明确操作；每个操作给出是否需卸载、空间需求、影响、验证和恢复方式。只读与可写状态分别可见，失败不显示为已激活。

## 8. 实验与实施顺序

第一轮仍用本机 Go SDK 的独立副本，内置盘完成；SDK 映像虚拟上限 2 GiB，初始空缓存映像上限 4 GiB。缓存随数据增长并不预占满，但执行前应预留原本、对照映像、压缩/转移副本、缓存和临时输出所需空间；不能按虚拟上限相加或仅按 SDK 占用判断空间够用。无自动扩容；到阈值提示并停止可能失败的操作。

实验按次序比较：未压缩只读 SDK + 空可写缓存 → ULFO SDK + 新的空缓存 → ULFO SDK + 热缓存 → 缓存卸载重挂 → 已卸载映像本地转移副本 → 重新挂载验证。使用 SDK 自带测试文件，不开发应用代码；验收 SDK 自动路径识别、基础离线编译、标准库测试、只读写入被拒绝、缓存写入定位、原环境无变化、缺卷时明确失败。Go 工作区和用户工具不纳入实验。

压缩测试记录转换耗时、宿主体积、首次挂载时间、冷/热编译时间和校验结果；比较冷缓存时必须使用各自全新缓存，不能让前一个测试预热后一个。不预设压缩率或速度目标。compact 测试仅创建并删除一份实验自有的可丢弃数据，比较回收结果；回收为零也属于合法结果，需报告原因。随后测试缓存归档、还原和复用；不删除真实缓存作测试。

第二轮新下载官方 .NET arm64 SDK 包，固定版本及摘要，验证只读根目录、CLI 状态、NuGet 路径、基础项目创建/编译/运行、原有 root 安装不变。依赖恢复的网络阶段与离线阶段分开记录，缺包时不声称能够离线恢复。

通过 Go/.NET 实验后再确定性能默认值，并实现只读 CLI/MCP、SwiftUI 查看与计划；最后接入经测试的挂载和维护事务。外置 SSD、Rust、Android、SDK 更新与回滚分别作为后续验收，Flutter 严格只读继续暂缓。

停止条件统一为：来源或版本变化、错误路径/卷身份、空间不足、只读兼容性失败、未经预期的宿主写入/下载/原安装回退、校验不一致、卷忙或断连。当前工作只交付本设计，不执行上述实验。

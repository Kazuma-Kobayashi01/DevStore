# Claude 移交说明

## 当前结论

DevStore 处于规划和实验阶段。当前方案是每个环境一个可写 APFS 卷，包含 SDK/runtime、原生工具管理器、状态、用户工具、必要依赖和缓存。固定挂载到 `~/.local/dev/<kind>/current`，映像可以存在外置 SSD。CLI/MCP 与 SwiftUI 是未来实现方向，目前没有 Swift 工程。

用户最后授权的是整理本移交项目；之前暂不编写管理器应用代码的要求仍在。不要把待办当作自动执行授权；用户后续明确指定实现或实验阶段时，再按其范围推进。原环境的迁移、切换、删除和全局 shell 修改不属于已完成的单卷副本测试。

## 必须保留的限制

1. Conda 前缀不是任意可搬目录。本次使用 conda-pack 0.9.2 的前缀处理，并固定挂载路径；跨盘可保持该路径，跨用户名/Mac/架构仍须重新验证。
2. 源包缓存基本清空，存在前缀重写警告；base 的 python.app 也有 post-link 后实际布局与旧记录不同的问题。报告记录了定向处理，不应把它概括成没有警告的完整再安装。
3. 最初直接复制输出漏项，python3.10 的三项测试失败；归档完整性检查捕获后用 tar 重建并通过。首次失败记录仍在，最终 69/69 是修复后通过的三轮，不是从未失败。
4. 未验证全部包、Python GUI、GPU/MPS、在线升级、外置 SSD、跨 Mac、秘密迁移或 compact 中断。不要把环境名 llama-cpp 当成已测模型推理。
8. 现有 Miniconda 映像（含 lab 槽位副本）中有 703 个二进制、7,784 个 pyc 硬编码原安装路径 `~/miniconda3`；测试能力不依赖它们，但原安装移走后个别工具可能静默回退或失败。见[多槽实验](reports/多槽实验结果-20261029.md)。
5. 环境卷仍依赖宿主 macOS；Xcode、系统框架、虚拟化能力、钥匙串身份等需明确登记。它不是进程隔离容器。
6. 单卷可写环境与停用压缩归档不同：归档格式本身只读，实际运行要恢复成可写卷。
7. 大型映像副本和压缩检查点在同一物理盘，不是独立物理备份；克隆拷贝同样如此。

## 建议后续顺序

2026-10-29 已完成 compact 与多槽实验（[compact](reports/compact实验结果-20261029.md)、[多槽](reports/多槽实验结果-20261029.md)），设计决定见 [v3 数据模型](design/v3数据模型.md)。该实验的派生映像已按用户决定删除，证据与参数化脚本（`artifacts/experiment-support/compact-multislot-20261029/`）保留。

收到新的实验请求时，先核实当前挂载和路径状态。可以优先补齐外置 SSD 转移、compact 中断（A10）和受控升级/回滚测试；所有步骤均以新的受管理副本进行，不动日常安装。

收到产品实现请求时，先收敛 v3 的数据模型与能力边界：环境身份、适配器路径映射、宿主依赖、映像登记、挂载事务、会话环境、检查点/归档恢复、缓存分类与验证证据。初版先支持已验证的 Miniconda 适配器，不默认批量迁移所有 SDK。

Swift CLI、MCP Server、SwiftUI 共用核心服务。只读 inspect/plan 与实际写入/挂载/升级的能力区分清楚；授权绑定具体实例和动作，不能接受 Agent 自报的 confirmed 标志作为授权。入口可限定为登记的工具，但构建脚本仍可能执行用户代码，需要遵守宿主权限范围。

Go 和官方独立 .NET 二进制包适合后续验证；Rust 保持完整 RUSTUP_HOME/CARGO_HOME，Flutter 保持原生写入，Android 可把独立 JDK 和混合 Gradle/Android 状态同卷。它们的单卷适配尚未实现或验收。
